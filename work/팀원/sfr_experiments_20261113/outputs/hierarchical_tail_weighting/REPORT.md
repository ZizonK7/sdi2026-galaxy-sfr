# 극단값 학습 가중치 실험

기존 계층형 46피처 모델에서 꼬리 회귀기의 학습 가중치만 바꿨다. HGB400과 LightGBM400/31 각각에 대해 극단값 가중치 1·2·3·5배를 비교했다. 가중치 1은 각 회귀기 자체의 기존 결과다.

## 결과 판단

모든 고정 가중치 설정에서 두 시드 모두 전체 RMSE가 증가했다. 전체 로그 RMSE가 최종 평가 기준이라면 이번 가중치 설정을 채택할 근거는 부족하며, 무가중치 기준 모델을 유지하는 편이 타당하다.

두 시드에서 같은 계열의 무가중치 모델보다 극단값 RMSE가 모두 감소한 설정: HGB ×3, HGB ×5, LightGBM ×2, LightGBM ×3, LightGBM ×5.

그중 전체 RMSE도 두 시드에서 모두 감소한 설정: 없음.

실제 0과 극단값 RMSE가 두 시드에서 함께 감소한 설정: HGB ×5, LightGBM ×3. 구간별 개선이 전체 점수 개선과 동일한 것은 아니다.

위 비교는 고정된 후보들의 관측 결과다. 같은 관측치로 분할을 바꾼 반복 실험이므로 작은 차이가 독립 테스트에서 재현된다고 단정할 수 없다. 0 구간까지 포함한 변화율과 내부 선택 절차의 성능을 아래에 함께 기록했다.

## 고정한 조건

- 두 HGB 분류기, 일반 HGB 회귀기, 46개 피처, 꼬리 경계 SFR=10, P(0)≥0.9의 0 처리 규칙을 고정했다.
- 꼬리 전문가는 **실제 SFR>10인 학습 행**에만 학습했다. 분류기가 예측한 꼬리 행으로 학습하지 않았다.
- 목표는 log10(1+SFR). 10<SFR≤100의 학습 가중치는 1, SFR>100은 1·2·3·5다. 가중치를 별도로 정규화하지 않았다.
- 가중치는 꼬리 회귀기의 학습 손실에만 적용했다. **평가 RMSE에는 가중치를 적용하지 않았다.**
- HGB는 400회·31잎·학습률0.08·early_stopping=False, LightGBM은 400트리·31잎·학습률0.08·reg_lambda=0이다. 기타 설정은 weighted_tail.py 참조.
- 비교는 원래 train80%의 동일한 seed42/7 5-fold OOF다. 원래 holdout20% 정답은 사용하지 않았다.
- 전체 학습 행 166,749개, SFR>10은 11,696개, SFR>100은 209개다.
- 전체 RMSE는 5개 fold RMSE의 평균이다. 구간별 RMSE는 합친 OOF의 해당 실제 정답 구간에서 계산했다. 모두 로그 공간의 점수이며 낮을수록 좋다.

## 내부 검증으로 가중치를 고르는 절차의 성능

각 바깥 fold의 학습 데이터만 다시 80:20으로 나누고, 그 안에서 46피처의 잔차 계산·두 분류기·일반 회귀기·꼬리 회귀기를 학습했다. 내부 검증의 **최종 혼합 전체 로그 RMSE**가 가장 낮은 설정을 골라 바깥 학습 데이터 전체로 재학습한 예측을 평가했다. 바깥 검증 정답은 그 fold의 가중치 선정에 사용하지 않았다. 이는 한 번의 내부 holdout을 둔 중첩 평가이며, 내부 전체 교차검증은 아니다.

## 0과 극단값 해석

모든 후보의 0 출력 행과 0 판정 precision/recall은 동일했다. 실제 0의 RMSE 변화는 0으로 고정하지 않은 행에서 꼬리 전문가의 예측이 혼합값에 영향을 준 결과다.

극단값 가중치는 큰 값의 오차를 학습 과정에서 더 중요하게 만든다. 그러나 극단값 과대예측이나 다른 구간 오차 증가가 생길 수 있으므로 전체 점수와 함께 판단해야 한다. SFR>100 평가는 209개 관측치이므로 fold별 결과도 확인할 필요가 있다.

## 모델 저장과 사용

최종 전체 train80% 안에서 별도의 내부 검증 절차로 선택한 설정은 **LightGBM ×1**다. 이 설정을 train80% 전체로 재학습해 selected_model.joblib로 저장했다. 외부 OOF에서 가장 좋아 보이는 설정을 골라 덮어쓴 것이 아니며, 현재 모델로 자동 채택한 것도 아니다.

가중치 2·3·5의 여섯 모델도 각각 저장했다. 모든 모델은 학습된 분류기·일반 회귀기·전처리를 포함한다. current_model.json과 기존 모델, GitHub는 변경하지 않았다.

- `hgb_w3.joblib`: HGB ×3. SHA256 `b9fc9a74ee2ca9a1f33f4b50cae3db18b5a8f904f87275062049a6d29812302d`.
- `hgb_w5.joblib`: HGB ×5. SHA256 `2399f9561eb53b0b4a67107e8083972daceab49647d38257a36d76e4a9b468d9`.

패키지 내 requirements.txt와 파이썬 모듈을 함께 사용한다. reference는 환경 피처 계산에 쓰는 원본 고정 카탈로그다.

```python
import sys
from pathlib import Path
import joblib
import pandas as pd
bundle = Path("/absolute/path/to/hierarchical_tail_weighting")
sys.path.insert(0, str(bundle))
from feature_pipeline import predict_sfr
model = joblib.load(bundle / "selected_model.joblib")
reference = pd.read_csv("/absolute/path/to/reference.csv").drop(columns="sfr_linear", errors="ignore")
new_table = pd.read_csv("/absolute/path/to/input.csv").drop(columns="sfr_linear", errors="ignore")
predictions = predict_sfr(new_table, model, reference)
```

실험 재실행은 원본 데이터와 이전 hierarchical_gate46 및 hierarchical_tail_models 폴더의 모델·메타데이터·OOF 파일을 필요로 한다. 예측 실행에는 이전 폴더가 필요하지 않다.

```bash
python run_experiment.py --data /absolute/path/to/data.csv \
  --source-dir /absolute/path/to/hierarchical_gate46 \
  --tail-source-dir /absolute/path/to/hierarchical_tail_models \
  --cache /absolute/path/to/feature_search_cache
```

## 검증

저장한 OOF로 점수 2,398개를 재계산했다. 기존 HGB·LightGBM 기준 예측 재현, 고정 확률과 일반 회귀값을 사용한 최종 혼합 예측 재구성, 내부 선택 재현, 내부/외부 검증 행 분리, 학습 가중치 합과 극단값 개수, 0 출력 동일, 모델 해시를 확인했다. 학습 실행에서는 저장/재로딩 일치, 분류기·일반 회귀 예측 고정, 원시 입력 인터페이스도 검증했다. 별도 테스트 3개로 SFR=100 경계, 비꼬리 입력 거부, 동일 피처일 때 가중 로그 평균을 예측하는지 확인했다.

선정 규칙은 protocol.json, 데이터·버전·모델 해시는 metadata.json, 검증 결과는 validation.json에 있다. 원본 데이터는 배포 ZIP에 포함하지 않았다.
