# 평가 기준 변경과 최종 보고서 계획 (2026-11-11)

한 줄 요약: 1차 평가 기준이 선형 RMSE가 아니라 **로그 SFR 공간의 RMSE**로 확인됐다. 최종 모델은 조장 Part II 초안의 구조와 1단계 환경 분류기를 그대로 두고, **2단계 회귀기만 로그 타깃으로 바꾼다.** 선형 기준에서 하려던 꼬리 앙상블과 Gamma 손실 실험은 접는다.

템플릿의 고정 평가 칸(`evaluate_sfr`, `FINAL_SCORE`)은 선형 RMSE 그대로다. 이 칸은 고치지 않고, 로그 지표를 옆에 따로 보고한다.

## 2. 로그 기준에서 지금 모델은 어떤가

학습 데이터 안 5-fold CV(seed 42) 한 번으로 빠르게 쟀다. 검증 데이터는 쓰지 않았다. 로그의 정의가 공지에 없어 세 가지로 쟀다. 단위는 dex, 낮을수록 좋다.

| 모델 | log10(1+SFR) | log10(SFR+0.01) | log10(SFR), 양수만 |
|---|---:|---:|---:|
| 선형 기준선 (13개 피처) | 0.147 | 0.577 | 0.211 |
| Part II 초안: 환경 분류기 × 선형 회귀 | 0.129 | 0.398 | 0.210 |
| Part II 초안 + 팀원 꼬리 분리 T=30 | 0.113 | 0.359 | 0.176 |
| 로그 타깃 직접 회귀 (13 + 환경 17) | 0.108 | 0.269 | 0.161 |
| **환경 분류기 × 로그 회귀** | **0.104** | **0.259** | **0.161** |

- 로그 타깃으로 학습한 모델이 세 정의 모두에서 가장 좋다. Part II 초안보다 19~35% 낮다.
- 선형 기준에서 점수를 정하던 극단 꼬리는 비중이 사라진다. Part II 초안 모델의 오차제곱합에서 SFR > 100이 차지하는 비중은 선형 기준 85%에서 로그 기준 0.4~2.4%가 된다.
- 대신 SFR = 0 은하의 비중이 1% 미만에서 19%(log10(1+SFR)) 또는 75%(log10(SFR+0.01))로 커진다. 환경 분류기가 점수에 직접 기여하게 된다.
- 팀원의 꼬리 분리는 로그 기준에서도 양수 은하의 오차를 줄인다(0.121 → 0.105). 다만 로그 타깃 모델이 그보다 낫다.

한 번의 5-fold이고 구간 추정을 하지 않았으므로 0.104와 0.108 같은 작은 차이는 아직 해석하지 않는다. 코드와 원수치는 [`log_metric_check_2026-11-11/`](log_metric_check_2026-11-11/)에 있다.

## 3. 계획

### 최종 모델
- **1단계는 그대로**: 원래 13개 + 환경 17개로 P(SFR > 0 | x)를 내는 HGB 분류기.
- **2단계를 바꾼다**: SFR > 0인 은하로 학습한 HGB 회귀기의 타깃을 선형 SFR에서 로그 SFR로.
- 두 단계를 로그 공간에서 합친다: E[z | x] = P(SFR > 0 | x) · E[z | SFR > 0, x] + (1 − P) · z(0). z는 로그로 바꾼 SFR, z(0)은 SFR = 0의 로그 값이다.
- 템플릿이 요구하는 `VAL_PREDICTIONS`는 선형 SFR이어야 하므로 로그 예측을 되돌려 넣는다.

### 실험 순서
1. 로그 정의 확정(4절의 질문 1). 답이 오기 전에는 log10(1+SFR)을 기본으로 두고 다른 정의도 함께 잰다.
2. "환경 분류기 × 로그 회귀"를 반복 CV(5-fold × seed 5개)로 확인한다. 2단계 회귀기에 환경 피처를 넣을지(13 대 13+17)도 여기서 정한다.
3. 팀원의 꼬리 분리를 로그 모델 위에 얹어 비교한다. 로그 공간에서는 꼬리가 눌리므로 이득이 없을 수 있다.
4. 판단은 계속 학습 데이터 안 CV로 하고, 검증 데이터는 최종 후보를 고정한 뒤 한 번 쓴다.

### 접는 것
- 2단계 회귀기의 Gamma 손실, 꼬리 회귀기 배깅 앙상블. 둘 다 선형 공간의 극단값을 겨냥한 처방인데 로그 기준에서는 그 구간의 비중이 2% 아래다. Gamma는 중간 보고서 7절의 Poisson 결과(같은 계열, 선형 RMSE에서 나빴음)로도 기대가 낮았다.
- 환경 피처를 선형 회귀기에도 넣는 변형 (f)의 재검토. 로그 회귀기에서 다시 본다(실험 2).

### 보고서
- Part I(중간 제출본)은 선형 RMSE 기준으로 쓴 그대로 둔다. 7절의 "지표를 바꾸면 승자가 바뀐다"(log1p 모델이 MAE와 SFR = 0에서 가장 좋았음)가 Part II로 넘어가는 연결 고리다.
- 9.1에 "평가 기준이 로그로 확인되어 타깃 처리를 바꿨다"를 첫 변경으로 적는다. 9.2~14절은 로그 기준으로 다시 쓴다.
- 10절 비교 표에는 템플릿의 선형 지표와 로그 RMSE를 함께 싣는다.
- 11절 오차 분석의 주인공이 바뀐다. 선형에서는 극단 꼬리였고, 로그에서는 SFR = 0 판정과 낮은 SFR(0~1) 구간이다.
- 팀원의 꼬리 실험(`work/팀원/james_tail.ipynb`)은 "선형 기준에서 꼬리를 어떻게 다뤘고 왜 한계가 있었나"의 근거로 싣는다. 구간별 오차 비중 표, 예측/실제 비율, 가중치·하드 라우팅이 안 된다는 결과가 그대로 쓸 수 있는 내용이다.
- 4.1은 2026-11-08 요약의 요청대로 "Feature engineering: 없음"을 환경 피처 17개로 고친다. 팀원이 11-11에 넣은 근거 숫자(센티널 88.1%, 범위 폭 2,100배, 질량 열 상관 0.97~0.98, 위치·속도 날것은 나머지와 무관)는 그대로 쓴다.
- 평가 데이터에 바로 적용할 수 있게, 피처 계산부터 예측까지를 라벨 없는 표 하나를 받는 함수로 묶어 9.2에 둔다(Q2).

## 4. 주최 측에 확인할 것

1. **SFR = 0의 로그를 어떻게 계산하는가.** log10(1+SFR)인지, 작은 값을 더하는지, 다른 방식인지. 0 은하의 오차 비중이 19%에서 75%까지 달라지고 학습할 타깃 변환이 달라진다.
2. **평가 데이터가 어떻게 주어지는가.** 학습 은하와 같은 상자의 은하가 함께 주어지는지, 평가 은하만 따로 주어지는지. 따로 주어지면 이웃 수 같은 환경 피처 값이 학습 때와 달라진다.
