### 0.3 블록 진행 규칙 (반드시 지킬 것)
1. 블록 시작 시 위치를 표시한다: `[1단계 1/4] 회귀 트리는 축에 평행한 칸 나누기다` / `[실습 2/3] …` / `[2단계 1/3] …`
2. **'한 문장 직관'을 먼저 말한다.**
3. 그 블록의 **[필수] 내용을 빠짐없이** 설명하고, 끝에 **확인 문제**를 던진 뒤 **멈추고 학습자의 응답을 기다린다.**
4. 학습자가 질문하면 답하고, 같은 블록 안에서 이해를 다시 확인한다.
5. 학습자가 이해했거나 "다음"이라고 하면 다음 블록으로 넘어간다.
6. 확인 문제에 막히면 "막히면" 항목의 보충 설명을 쓰고, 이해 후 넘어간다.
7. 다음 블록 내용을 미리 당겨 설명하지 않는다.
- **수업 시작**: 첫 블록 전에 수업 전체의 한 문장 직관(§1)을 먼저 말한다. 블록을 잘게 쪼개지 않는다.
- **이미 배운 것은 다시 가르치지 않는다.** "이미 배움 →" 한 줄만 말하고 넘어간다. 잊었다고 하면 그 경로의 블록을 함께 열어 1~2분만 본다.

### 0.4 실습 블록 진행 규칙
1. 할 일을 말하고 코드 블록을 준다. 어느 칸 뒤에 붙이는지 짚는다.
2. 출력을 받으면 "받아야 할 출력"과 대조한다. 셋째 자리 차이는 무시. 템플릿에 저장된 기준선 RMSE 9.525와 실측 9.513의 차이는 scikit-learn 버전 차이 `[추정]`.
3. 오류는 "디버깅 체크리스트" 순서로. 확인 문제는 `(코드 읽기)` `(그림 읽기)` `(검토)` `(계산)`.
4. 하이퍼파라미터 실험은 **val로 고르지 않는다** — 실습 2/3은 "곡선을 보는 것"이고 고르는 것은 실습 3/3의 CV다. 이 구분을 흐리지 않는다.

### 0.5 이 수업에서 특히 주의할 점
- 학습자는 **GD·과적합·CV를 수식으로 안다.** 트리 모델에 그것을 **대응**시키는 데 집중한다("잔차 = 음의 기울기", "잎 수 = 클래스 크기").
- 템플릿 기준선의 숨은 사실: `early_stopping="auto"`는 n > 10,000이면 **켜진다** → `max_iter=150`인데 실제로는 **37번째 트리에서 멈췄다**(train의 10%를 내부 검증으로 떼어 10번 연속 개선 없으면 멈춤). 보고서 7.1 "Important hyperparameters"에 이것을 모르고 "150 trees"라고 쓰면 틀린다.
- CV의 fold별 RMSE가 5.4~14.4로 요동한다. 이것은 버그가 아니라 1-1 2단계 2/2(점수는 꼬리가 정한다)의 결과다. 학습자가 "CV가 이상하다"고 하면 그 블록으로 돌려보낸다.

## 1. 수업 개요
- **수업 전체 한 문장 직관**: 부스팅은 작은 트리를 하나씩 더해 가며 그때까지 틀린 만큼을 조금씩 고치는 방법이다.
- **한 줄 요약**: 회귀 트리(축에 평행한 칸 나누기, 잎 = 평균)를 잔차에 반복해 맞춰 더하는 것이 그래디언트 부스팅이고, 템플릿 기준선 HGB는 이것을 히스토그램으로 빠르게 한 것이다.
  학습률·트리 수·잎 수가 무엇을 바꾸는지 곡선으로 보고, 하이퍼파라미터는 `X_train` 안 5-fold CV로 고르되 fold 잡음(5.4~14.4) 아래의 차이는 차이가 아님을 확인한다. 수학으로는 부스팅이 함수 공간의 경사하강법임을 유도한다.
- **수업 흐름**: 1단계(트리 → 부스팅 → HGB·early stopping → 기준선 표) → 실습(재현·37회 → 곡선 → CV) → 2단계(함수 공간 GD → 분할 기준 → 일반화·CV 잡음).
- **선수 지식(연결)**: 심수기 1·2-2·7-2, 자분실 7·9, 1-1 2단계 2/2.
- **다음 회차 연결**: 2-1은 같은 모델로 **손실**(MSE / log 변환 / Poisson)과 **구조**(2단계 P×E)를 바꿔 비교한다.

### 2.3 블록 상세

#### [1단계 1/4] 회귀 트리는 축에 평행한 칸 나누기다
- **한 문장 직관**: 회귀 트리는 피처 공간을 "이 열이 이 값보다 작나?"라는 질문으로 칸을 나누고 칸마다 평균을 내놓는 계단 함수다.
- **블록 목표**: (1) 트리 하나가 어떤 꼴의 함수인지 그릴 수 있다. (2) "트리는 단조 변환에 불변"과 "센티널을 분할로 떼어낸다"를 설명할 수 있다 — 1-1에서 미뤄 둔 두 결정의 근거.
- **설명할 내용**
  - [필수] **구조**: 뿌리에서 질문 하나(`log10_overdensity_plus_1 ≤ 1.48?`)로 둘로 나누고, 각 가지에서 또 질문… 끝 칸이 **잎(leaf)**. 예측 = 그 잎에 든 훈련 은하들의 **y 평균**. 이미 배움 → 자분실 7 `[2단계 3/9]` 손실이 평균과 중앙값을 낳는다 (`자료분석 및 실습/중간고사/7_수업정리.md`): 제곱 손실의 상수 최적값은 평균. **이 대회에서는**: 잎마다 그 상수 최적화를 하는 것이 회귀 트리다(2단계 2/3에서 분할 기준도 여기서 나온다).
  - [필수] **크기**: `max_leaf_nodes`(잎 수) 또는 `max_depth`. 잎 31개 = 피처 공간을 31칸으로. 잎이 많을수록 더 잘게 나눈 계단 → 훈련 데이터에 더 맞고 새 데이터엔 위험(2단계 3/3).
  - [필수] **단조 변환 불변**: 질문이 "≤ t?"뿐이라 피처의 **순서**만 쓴다. x를 log x, 표준화한 x로 바꿔도 같은 순서 → **같은 트리**. 그래서 1-1에서 표준화를 안 했다.
  - [필수] **센티널**: `log10_mass_ratio ≤ −5.9?`라는 질문 하나로 "병합 없음(−6)" 84%를 따로 떼어낸다. 선형 모델처럼 −6을 숫자로 더하지 않는다 → 1-1에서 센티널을 그대로 둔 근거.
  - [필수] **한계**: 축에 평행한 칸만 만든다 → 대각선 경계(예: stellar − halo 비)는 계단으로 근사해야 하고 트리가 많이 필요하다. 그래서 비율·차이 피처가 트리에 도움이 될 수 있다(완벽 ver의 피처 공학 근거). 또 잎 평균이므로 **훈련 y의 범위 밖을 예측하지 못한다**(외삽 불가) — 꼬리 과소예측의 한 원인.
- **확인 문제**
  1. `(계산)` 훈련 은하 6개의 (밀도, SFR) = (0.2, 3), (0.5, 2), (0.9, 4), (1.6, 0), (1.9, 1), (2.3, 0). 질문 "밀도 ≤ 1.25?"로 나눈 트리(잎 2개)의 두 예측값과, 그 트리의 훈련 SSE를 구하라. 분할 전 SSE(잎 1개)는?
     - 모범 답: 왼쪽 잎 평균 (3+2+4)/3 = **3**, 오른쪽 (0+1+0)/3 = **1/3**. SSE = (0+1+1) + (1/9+4/9+1/9) = 2 + 2/3 = **2.67**. 분할 전: 평균 10/6 = 1.667, SSE = Σy² − nȳ² = 30 − 6·2.778 = **13.33**. 채점 포인트: 잎 = 평균, SSE가 13.3 → 2.7로 준 것.
  2. `(참/거짓 + 이유)` "`log10_stellar_mass` 대신 10^(log10_stellar_mass)(선형 질량)을 피처로 넣으면 트리 모델의 예측이 달라진다."
     - 모범 답: **거짓.** 10^x는 단조 증가라 순서가 같고 분할 후보가 같아 같은 트리가 나온다(히스토그램 구간 경계가 약간 달라질 수는 있다 `[보충: HGB의 binning은 분위수 기반이라 단조 변환에 거의 불변]`). 채점 포인트: 순서만 쓴다.
  3. `(짧은 서술)` 훈련 데이터의 최대 SFR이 2,145인데 검증에 SFR 3,000짜리 은하가 있다면 트리 모델은 어떻게 되나? 선형 회귀라면?
     - 모범 답: 트리는 잎 평균만 내놓으므로 **2,145를 넘는 값을 절대 못 낸다**(실제로는 잎 평균이라 그보다 훨씬 작다). 선형 회귀는 직선을 연장해 외삽할 수 있다(맞을지는 별개). 채점 포인트: 외삽 불가.
- **막히면**: 1-1 그림 B(밀도별 0 비율)를 떠올리게 한다 — "밀도 1.5에서 자른다"가 바로 트리의 질문 하나이고, 그 뒤 "질량으로 또 자른다"가 두 번째 층이다.
- **다음 블록 연결**: 트리 하나는 계단이 거칠다. 거친 트리를 **여러 개 더해** 부드럽게 만드는 것이 부스팅이다.

#### [1단계 2/4] 부스팅은 잔차에 트리를 맞춰 더하기다
- **한 문장 직관**: 지금까지의 예측이 틀린 만큼(잔차)에 작은 트리를 맞춰서 그 일부를 더하는 일을 반복한다.
- **블록 목표**: (1) 부스팅의 네 줄(초기값 → 잔차 → 트리 → 더하기)을 쓸 수 있다. (2) 학습률·트리 수·잎 수가 각각 무엇을 바꾸는지 말할 수 있다.
- **설명할 내용**
  - [필수] **알고리즘(제곱 손실)**:
    1. F₀(x) = ȳ (훈련 평균; 실측 y_train 평균 ≈ 3.70)
    2. m = 1, …, M에 대해: 잔차 rᵢ = yᵢ − F_{m−1}(xᵢ) → 잔차에 작은 트리 h_m을 맞춘다(잎 ≤ `max_leaf_nodes`) → **F_m = F_{m−1} + η·h_m**
    3. 예측 = F_M(x) = ȳ + η Σ h_m(x)
    이미 배움 → 심수기 1 `[2단계 3/8]` 경사하강법의 수학 (`심층신경망의 수학적 기초/중간고사/1_수업정리.md`), 공방 1-1 `[1단계 1/3]` 학습 루프 네 줄. **이 대회에서는**: 파라미터 대신 **함수 F**를 갱신하고, 기울기 대신 **잔차에 맞춘 트리**를 더한다 — 왜 잔차가 기울기인지는 2단계 1/3.
  - [필수] **세 하이퍼파라미터** (템플릿 기준선 값):

    | 인자 | 기준선 | 바꾸면 |
    |---|---|---|
    | `learning_rate` η | 0.08 | 한 걸음 크기. 작으면 트리가 더 많이 필요하고 보통 더 부드럽게 맞는다 |
    | `max_iter` M | 150 (실제 37, 다음 블록) | 트리 수 = 걸음 수. 많으면 훈련 오차는 계속 줄지만 검증은 멈추거나 나빠진다 |
    | `max_leaf_nodes` | 31 | 트리 하나의 크기 = 한 번에 잡는 상호작용의 복잡도. 잎 3 = 아주 거친 계단 |

  - [필수] **왜 작은 트리를 많이**: 큰 트리 하나는 훈련 데이터를 외우기 쉽다. 작은 트리는 각각 거칠지만 **다른 트리가 남긴 오차**를 고치므로 합은 부드럽고 복잡한 함수가 된다. η < 1로 "일부만" 더하는 것(shrinkage)이 과적합을 늦춘다.
  - [선택] 분류·Poisson 손실에서는 잔차 자리에 **손실의 음의 기울기**가 들어간다(2-1에서 Poisson). 랜덤 포레스트는 "독립적으로 만든 큰 트리들의 평균"으로 전혀 다른 원리다 — 이 대회에선 안 쓴다.
- **확인 문제**
  1. `(계산)` y = (0, 2, 4, 10) 네 점, 피처 x = (1, 2, 3, 4). η = 0.5, 잎 2개 트리(분할은 x ≤ 2.5로 고정). F₀와 1단계 뒤 F₁의 네 예측값, 그리고 F₁의 잔차를 구하라.
     - 모범 답: F₀ = 4. 잔차 r = (−4, −2, 0, 6). 트리: 왼쪽 잎(x ≤ 2.5) 평균 −3, 오른쪽 평균 3. F₁ = 4 + 0.5·(−3, −3, 3, 3) = **(2.5, 2.5, 5.5, 5.5)**. 새 잔차 = (−2.5, −0.5, −1.5, 4.5). 채점 포인트: 잎 평균, η 곱하기, 잔차가 줄었는지(SSE 56 → 29.0).
  2. `(참/거짓 + 이유)` "학습률을 0.08에서 0.02로 낮추면 같은 트리 수에서 훈련 오차가 더 빨리 준다."
     - 모범 답: **거짓.** 걸음이 1/4이라 같은 트리 수에서는 **덜** 줄어든다(실측 CV: 0.02·150은 0.08·150과 비슷한 수준이지만 early stopping이 더 많은 트리를 쓴 결과). 낮은 학습률의 이점은 속도가 아니라 더 많은 작은 걸음으로 부드럽게 맞추는 것. 채점 포인트: η와 M의 맞교환.
  3. `(짧은 서술)` 트리 수를 1,000으로 늘렸는데 검증 RMSE가 150일 때와 거의 같았다(실측 9.67 → 9.66, 훈련은 4.94 → 1.73). 무슨 일이 일어난 것인가?
     - 모범 답: 트리를 더할수록 훈련 잔차는 계속 줄지만(외우기), 검증에서 더 맞힐 수 있는 구조는 이미 다 잡았고 나머지는 노이즈라 검증은 제자리 → **과적합 영역**(해로울 수도 있는데 이 데이터에선 평평). 2단계 3/3에서 approximation–estimation으로 다시. 채점 포인트: 훈련↓·검증= 의 해석.
- **막히면**: 1번 계산을 수직선에 그려 "평균 4에서 시작해 왼쪽 둘은 1.5 내리고 오른쪽 둘은 1.5 올린" 것으로 보인다. 다음 트리는 또 남은 차이를 반으로.
- **다음 블록 연결**: 템플릿의 HGB는 이 알고리즘에 두 가지 공학을 더했다 — 히스토그램과 자동 early stopping. 둘째 것이 기준선 해석을 바꾼다.

#### [1단계 3/4] HGB와 early stopping — 기준선은 37번에서 멈췄다
- **한 문장 직관**: HGB는 피처를 255개 구간으로 묶어 분할을 빠르게 찾고, 내부 검증이 10번 연속 안 좋아지면 스스로 멈춘다.
- **블록 목표**: (1) `HistGradientBoostingRegressor`의 기본 인자 중 결과를 바꾸는 것(early stopping·binning)을 안다. (2) 기준선 `max_iter=150`이 실제 트리 수가 아님을 알고 `n_iter_`로 확인하는 습관을 갖는다.
- **설명할 내용**
  - [필수] **히스토그램**: 연속 피처를 분위수 기준 **최대 255개 구간**(`max_bins=255`)으로 묶고, 분할 후보를 구간 경계에서만 찾는다 → 20만 행에서 트리 하나가 밀리초. 그래서 기준선이 0.5초. (LightGBM·XGBoost의 hist 방식과 같은 아이디어 — LightGBM은 선택 사항.)
  - [필수] **early stopping = "auto"**: 훈련 표본이 **10,000개를 넘으면 자동으로 켜진다**. `validation_fraction=0.1`로 `X_train`의 10%(16,675개)를 내부 검증으로 떼어 매 트리마다 그 손실을 재고, **`n_iter_no_change=10`번 연속 개선(`tol=1e-7`)이 없으면 멈춘다.** 멈춘 트리 수가 `BASELINE_MODEL.n_iter_`. **Claude 실측: 37.** 즉 기준선은 (a) train의 90%로 학습했고 (b) 트리 37개다. `max_iter=150`은 **상한**일 뿐.
  - [필수] **왜 이게 중요한가**: 보고서 7.1 "Important hyperparameters"에 "150 trees"라고 쓰면 틀린 진술이다. 또 early stopping을 끄면(`early_stopping=False`) 전체 train으로 150개를 다 쓰고, 실측 val RMSE는 9.67(켰을 때 9.51)로 오히려 조금 나빠진다 — 트리를 더 쓴 것이 꼬리 몇 개에서 손해 `[추정: 꼬리 요동]`. 결과를 비교할 때 **같은 early stopping 설정**인지 확인한다.
  - [필수] **그 밖의 기본값**: `l2_regularization=0`, `min_samples_leaf=20`(잎에 최소 20개), `max_depth=None`(잎 수로만 제한), `loss="squared_error"`(2-1에서 `"poisson"`으로 바꾼다), `random_state`는 내부 검증 분할과 binning 서브샘플에 쓰인다.
  - [선택] `categorical_features`, 결측 처리(NaN을 분할마다 한쪽으로 보냄 — 이 데이터엔 NaN이 없어 무관), `interaction_cst`.
- **확인 문제**
  1. `(코드 읽기)` 템플릿 기준선 셀을 그대로 두고 `BASELINE_MODEL.n_iter_`를 찍으면 37이다. (a) 이 모델이 학습에 실제로 쓴 행 수는? (b) `max_iter=50`으로 바꿔 다시 돌리면 `n_iter_`는? (c) `max_iter=500`이면?
     - 모범 답: (a) 166,749 × 0.9 ≈ **150,074**. (b) 37 (상한 50 안에서 같은 자리에 멈춤 — 실측 CV에서 50과 150·500이 **똑같은** fold RMSE). (c) 37. 채점 포인트: `max_iter`는 상한.
  2. `(검토)` 팀원이 7.1에 "Hyperparameters: learning_rate=0.08, 150 trees, 31 leaves, trained on 166,749 galaxies"라고 썼다. 두 가지를 고쳐라.
     - 모범 답: 트리 수는 **37**(early stopping으로 멈춤, `n_iter_`), 학습 행 수는 **약 150,000**(10%는 내부 검증). "early_stopping='auto' → on, validation_fraction=0.1, n_iter_no_change=10"을 함께 적어야 재현 가능. 채점 포인트: 둘 다.
  3. `(짧은 서술)` early stopping을 켠 모델(37개, 90% 데이터)과 끈 모델(150개, 100% 데이터)의 검증 RMSE가 9.51 vs 9.67이다. 이 차이로 "early stopping이 더 좋다"고 결론 내릴 수 있나?
     - 모범 답: **아니다.** 1-1 2단계 2/2 — RMSE는 꼬리 몇 개로 0.9씩 움직인다. 0.16 차이는 그 잡음 안이다. 결론을 내리려면 구간(2-2 쌍 부트스트랩)이 필요하다. 채점 포인트: 차이의 크기 감각.
- **막히면**: early stopping을 "모의고사 점수가 10번 연속 안 오르면 공부를 멈추는 규칙"으로. 모의고사(내부 검증 10%)는 **본시험(val)이 아니다** — 그래서 val은 손대지 않은 채로 남는다.
- **다음 블록 연결**: 그 기준선이 어디서 잘하고 어디서 못하는지 — 템플릿 표의 네 줄을 읽는다.

#### [1단계 4/4] 기준선 표 읽기
- **한 문장 직관**: 기준선은 보통 은하는 잘 맞히지만 0을 1.2로 올려 예측하고 가장 활발한 은하는 1/3로 깎아 예측한다.
- **블록 목표**: (1) `evaluate_sfr` 표의 네 줄과 세 지표를 읽고 중앙값 기준선과 비교할 수 있다. (2) 기준선의 실패 모양(0 과대, 꼬리 과소, 음수 예측)을 말할 수 있다 → 6.1.
- **설명할 내용**
  - [필수] **표** (템플릿 저장값 / Claude 실측 — 셋째 자리 차이는 버전):

    | Regime | N | 중앙값 기준선 RMSE | HGB 기준선 MAE | HGB RMSE | HGB R² |
    |---|---|---|---|---|---|
    | All | 41,688 | 12.345 | 1.286 / 1.296 | 9.525 / **9.513** | 0.387 / 0.388 |
    | SFR = 0 | 3,610 | 1.633 (중앙값 1.63을 그대로 예측) | 1.176 / 1.214 | 3.421 / 3.551 | 0 (정의상) |
    | SFR > 0 | 38,078 | 12.907 | 1.296 / 1.303 | 9.911 / 9.894 | 0.388 / 0.390 |
    | Top 10% SFR (≥ 7.55) | 4,169 | 38.733 | 6.556 / 6.583 | 29.446 / 29.404 | 0.247 / 0.249 |

  - [필수] **읽는 법**: R²는 regime 안의 분산 대비 설명 비율(SFR = 0 줄은 분산 0이라 정의상 0 — 의미 없음, RMSE만 본다). All R² 0.39 = 분산의 61%를 못 설명. **Top 10%의 RMSE 29.4가 All의 9.5를 만든다**(1-1: SSE의 85%가 SFR > 100인 61개).
  - [필수] **실패 모양** (Claude 실측, 참 SFR 구간별 평균 잔차 ŷ − y):

    | 참 SFR | n | 평균 잔차 | RMSE | SSE 비중 |
    |---|---|---|---|---|

    | (20, 100] | 981 | −3.58 | 15.9 | 6.5% |

    그리고 **음수 예측 19개**(최소 −6.5) — 제곱 손실 트리는 잎 평균의 합이라 음수가 나올 수 있다(물리적으로 불가능; Poisson 손실은 양수만 — 2-1).
  - [필수] **6.1에 쓸 해석의 뼈대**: (1) 어려움: 중앙값 기준선 대비 RMSE 12.3 → 9.5로 23% 개선에 그친다 — 피처가 꼬리를 못 설명한다. (2) 실패 위치: 0을 평균으로 뭉개고(회귀 평균의 성질), 꼬리를 크게 과소예측(외삽 불가 + 꼬리 표본 270개). (3) 그래서 7절에서 시험할 것: 0을 따로 다루기, 꼬리에 맞는 손실.

- **확인 문제**
  1. `(계산)` SFR = 0인 검증 은하 3,610개의 MAE가 1.21, RMSE가 3.55다. 모든 0 은하를 정확히 0으로 맞혔다면 All RMSE(9.513)는 얼마가 되나?
     - 모범 답: 0 regime의 SSE = 3,610 × 3.55² = 45,497. All SSE = 41,688 × 9.513² = 3,772,600. 빼면 3,727,100 → RMSE = √(3,727,100/41,688) = √89.4 ≈ **9.456**. 0을 완벽히 맞혀도 0.06 개선 — 점수는 0이 아니라 꼬리에 있다. 채점 포인트: 제곱 척도 계산 + 결론.
  2. `(검토)` 6.1 초안: "기준선의 R²가 0.39로 낮으므로 더 복잡한 모델(트리 1,000개)이 필요하다." 두 군데를 반박하라.
     - 모범 답: (a) R²가 낮은 주된 이유는 **꼬리 61개**이고, 트리를 늘려도 꼬리는 외삽 불가·표본 부족이라 안 잡힌다(실측: 1,000개도 9.66). (b) "복잡한 모델"이 아니라 **문제 구조**(0과 꼬리)에 맞는 손실·구조가 필요하다. 채점 포인트: 복잡도 ≠ 해결.
  3. `(짧은 서술)` 템플릿 저장값 9.525와 학습자 실측 9.513이 다르다. 보고서에는 어느 쪽을 쓰고 어떻게 적나?
     - 모범 답: 자기 환경에서 **실행한 값**을 쓰고, 노트북 출력이 그 값이면 된다. 환경(scikit-learn 버전)을 14절 모델 카드에 적는다. 셋째 자리 차이는 결론에 영향 없다. 채점 포인트: 재현 가능성 관점.
- **막히면**: 표에서 "RMSE가 가장 큰 줄"을 손가락으로 짚게 한다. 그 줄이 All을 만든다.
- **다음 블록 연결**: 이제 노트북에서 37을 직접 확인하고, 세 하이퍼파라미터를 돌려 보고, 고르는 절차를 세운다.

### 2.4 대화용 핵심 용어·질문
- 용어: 회귀 트리(regression tree), 잎(leaf)·분할(split)·깊이(depth), 잔차(residual), 그래디언트 부스팅(gradient boosting), 학습률/shrinkage(η), 트리 수(`max_iter`, `n_iter_`), 잎 수(`max_leaf_nodes`), early stopping(`validation_fraction`, `n_iter_no_change`), 히스토그램 binning(`max_bins`), 단조 변환 불변, 외삽 불가, K-fold, 누출(leakage), 선택 후 낙관성

#### [실습 1/3] 기준선 해부
- **한 문장 직관**: 기준선을 "150개 트리"가 아니라 "37개 트리, 0을 +1.2, 꼬리를 −147"로 설명할 수 있어야 6.1이 된다.
- **할 일**: 6절 기준선 셀 뒤 새 칸에 붙여 실행.
  ```python
  # 6.1 재료: 기준선 해부 — 템플릿 변수 BASELINE_MODEL, baseline_pred, X_train, y_train, X_val, y_val 사용
  from sklearn.metrics import mean_squared_error
  rmse = lambda a, b: mean_squared_error(a, b) ** 0.5
  print("기준선이 실제로 쓴 트리 수 n_iter_:", BASELINE_MODEL.n_iter_, "| max_iter 상한:", BASELINE_MODEL.max_iter,
        "| early_stopping:", BASELINE_MODEL.early_stopping, "(n_train > 10,000 → 'auto'는 켜짐; 내부 검증 10%)")
  print(f"train RMSE {rmse(y_train, BASELINE_MODEL.predict(X_train)):.3f} | val RMSE {rmse(y_val, baseline_pred):.3f}")
  print(f"음수 예측: {(baseline_pred < 0).sum()}개, 최소 {baseline_pred.min():.2f} | 예측 최대 {baseline_pred.max():.1f} vs 참 최대 {y_val.max():.1f}")
  yv = y_val.to_numpy(); res = baseline_pred - yv
  tab = pd.DataFrame({"bin": pd.cut(yv, [-0.001, 0, 1, 5, 20, 100, 3000]), "res": res, "sq": res ** 2})
  g = tab.groupby("bin", observed=True).agg(n=("res", "size"), mean_res=("res", "mean"),
                                            rmse=("sq", lambda s: np.sqrt(s.mean())), sse_share=("sq", lambda s: s.sum() / tab["sq"].sum()))
  print(g.round(3))
  ```

- **디버깅 체크리스트**:
  1. `AttributeError: n_iter_` → 기준선 셀을 실행하지 않았다(또는 `BASELINE_MODEL`을 다른 모델로 덮어썼다). 템플릿 셀을 다시 실행.
  2. `observed=True` 오류 → 옛 pandas. 인자를 지운다.
  3. 숫자가 다름 → `RANDOM_SEED=42`로 공통 분할을 썼는지, 기준선 셀을 고치지 않았는지.
- **확인 문제**
  1. `(코드 읽기)` `sse_share` 열의 합은 1이다. (100, 3000] 구간 61개의 0.855를 뺀 나머지 41,627개가 0.145를 나눈다. 이 61개를 완벽히 맞히면 val RMSE는?
     - 모범 답: SSE가 14.5%로 → RMSE = 9.513 × √0.145 ≈ **3.62**. 채점 포인트: RMSE ∝ √SSE. (1-1 2단계 2/2의 "점수는 꼬리가 정한다"를 자기 출력으로.)
  2. `(검토)` 음수 예측이 있다. "`np.clip(pred, 0, None)`으로 0 아래를 잘라 내자"는 제안을 판정하라 — RMSE가 나아지나 나빠지나, 왜?
     - 모범 답: **절대 나빠지지 않는다.** 참값이 ≥ 0이므로 음수 예측 c < 0을 0으로 올리면 모든 참값에 대해 |0 − y| ≤ |c − y|. 효과는 작다(음수 예측이 소수). 7절 모델에서 해도 되고 7.1에 적는다. 채점 포인트: 단조 개선 논증.
- **막히면**: 구간표의 `n`과 `sse_share`를 나란히 읽게 한다 — 0.15%의 행이 85%의 오차.

#### [실습 2/3] 세 하이퍼파라미터 곡선
- **한 문장 직관**: 훈련 오차는 트리를 더할수록 끝없이 내려가지만 검증 오차는 30번쯤에서 바닥을 치고 평평해진다.
- **할 일**: 아래를 붙여 실행. `early_stopping=False`로 **일부러** 끄고 곡선을 본다(켜 두면 37에서 멈춰 곡선이 안 보인다). **이것은 val을 "보는" 실험이지 val로 "고르는" 것이 아니다** — 고르기는 다음 블록.

  # 하이퍼파라미터 곡선 (관찰용 — 선택은 다음 블록의 CV로). early stopping을 끄고 트리 수별 train/val RMSE
  m300 = HistGradientBoostingRegressor(early_stopping=False, learning_rate=0.08, max_iter=300, max_leaf_nodes=31, random_state=RANDOM_SEED).fit(X_train, y_train)
  tr_curve = [rmse(y_train, p) for p in m300.staged_predict(X_train)]
  va_curve = [rmse(y_val, p) for p in m300.staged_predict(X_val)]
  for k in [1, 5, 10, 20, 34, 50, 100, 150, 300]:
      print(f"trees {k:3d}: train {tr_curve[k-1]:.3f}  val {va_curve[k-1]:.3f}")

  plt.figure(figsize=(6, 3.5)); plt.plot(tr_curve, label="train"); plt.plot(va_curve, label="val"); plt.axvline(BASELINE_MODEL.n_iter_, ls="--", c="gray", label=f"baseline stopped at {BASELINE_MODEL.n_iter_}")

  for lv in [3, 7, 15, 31]:
      m = HistGradientBoostingRegressor(early_stopping=False, learning_rate=0.08, max_iter=150, max_leaf_nodes=lv, random_state=RANDOM_SEED).fit(X_train, y_train)
      print(f"leaves {lv:2d}: train {rmse(y_train, m.predict(X_train)):.3f}  val {rmse(y_val, m.predict(X_val)):.3f}")

- **디버깅 체크리스트**:
  1. 느림(> 30초) → `max_iter=300`이 150개 fit 4번과 합쳐 CPU에 따라 20~40초. 기다린다. 더 느리면 `max_iter=150`으로.
  2. `staged_predict` 없음 → scikit-learn이 아주 오래됐다(1.0 미만). 업데이트.
- **확인 문제**
  1. `(그림 읽기)` 검증 곡선이 34에서 최소(9.609)인데 템플릿 기준선(37에서 멈춤, 내부 검증 기준)은 9.513으로 **더 낮다**. 모순인가?
     - 모범 답: 아니다. 두 모델은 **다른 데이터**로 학습했다(기준선은 train의 90%). 0.1의 차이는 꼬리 요동 범위 안이다. 또 "val 최소 지점"을 골라 보고하면 **선택 후 낙관성**(자분실 9 `[1단계 8/8]` — 이미 배움) — 그래서 이 곡선으로 트리 수를 고르지 않는다. 채점 포인트: 데이터 차이 + 낙관성.
  2. `(계산)` 잎 31 → 3으로 줄이면 훈련 RMSE는 4.94 → 8.82로 **나빠지고** 검증은 9.67 → 9.41로 **좋아진다**. 두 숫자의 방향이 반대인 이유를 1-1·심수기 용어 하나로 말하라.
     - 모범 답: **과적합**(estimation error↑). 잎 31은 훈련 데이터의 노이즈·꼬리 몇 개까지 외우고(훈련↓), 그 외운 것이 새 데이터에선 틀린다(검증↑). 잎 3은 클래스가 작아 approximation은 못하지만 estimation이 작다 — 이 데이터에선 그쪽이 이득. 2단계 3/3에서 식으로. 채점 포인트: 방향 반대 = 과적합의 정의.
  3. `(검토)` 팀원: "잎 3이 val에서 가장 좋으니 7절 모델은 잎 3으로 간다." 절차상 문제는?
     - 모범 답: **val로 골랐다** — 공통 분할의 val은 최종 비교용(교수의 "손대지 않은 test"에 해당). 고르는 것은 `X_train` 안 CV로(다음 블록). val을 여러 번 보고 고르면 보고하는 val 점수가 낙관적이 된다. 채점 포인트: 선택과 평가의 분리.
- **막히면**: 심수기 2-2 `[2단계 3/9]`의 다항식 차수 M 그림(훈련 MSE 단조 감소, M = 9에서 과적합)을 떠올리게 한다 — 트리 수·잎 수가 그 M이다.

#### [실습 3/3] train 안 5-fold CV
- **한 문장 직관**: 하이퍼파라미터는 train을 다섯 조각으로 나눠 고르고, val은 7절 비교 때까지 손대지 않는다.
- **할 일**: 아래를 붙여 실행. `X_train`만 쓴다.
  ```python
  # 5.1 재료: X_train 안 5-fold CV로 하이퍼파라미터 비교 (val은 쓰지 않는다)
  from sklearn.model_selection import KFold
  kf = KFold(n_splits=5, shuffle=True, random_state=RANDOM_SEED)
  Xtr, ytr = X_train.reset_index(drop=True), y_train.reset_index(drop=True)
  folds = list(kf.split(Xtr))
  print("fold별 최대 y:", [round(float(ytr.iloc[te].max())) for _, te in folds], "| fold별 SFR>100 개수:", [int((ytr.iloc[te] > 100).sum()) for _, te in folds])
  grid = [(0.08, 150, 31), (0.08, 150, 7), (0.08, 150, 3), (0.08, 500, 31), (0.02, 150, 31), (0.3, 150, 31)]
  cv_rows = []
  for lr, it, lv in grid:
      t0 = time.time(); fold_rmse = []
      for tr, te in folds:
          m = HistGradientBoostingRegressor(learning_rate=lr, max_iter=it, max_leaf_nodes=lv, random_state=RANDOM_SEED).fit(Xtr.iloc[tr], ytr.iloc[tr])
          fold_rmse.append(rmse(ytr.iloc[te], m.predict(Xtr.iloc[te])))
      cv_rows.append({"lr": lr, "max_iter": it, "leaves": lv, "cv_rmse": np.mean(fold_rmse), "fold_sd": np.std(fold_rmse, ddof=1),
                      "folds": [round(f, 2) for f in fold_rmse], "sec": round(time.time() - t0, 1)})
  cv_table = pd.DataFrame(cv_rows)
  print(cv_table.round(3).to_string(index=False))
  ```
- **받아야 할 출력** (Claude 실측): fold별 최대 y `[2145, 1414, 564, 463, 334]`, SFR > 100 개수 `[58, 49, 31, 36, 35]`. 표(cv_rmse / fold_sd / folds):
  (0.08, 150, 31) **8.325** / 3.99 / [14.44, 10.32, 6.01, 5.40, 5.45] · (0.08, 150, 7) 8.427 / [14.41, 10.61, 6.05, 5.60, 5.46] · (0.08, 150, 3) 약 8.4~8.5 `[추정: 이 설정은 Claude가 CV로는 돌리지 않음 — val에서만 9.41]` ·
  (0.08, 500, 31) 8.325(150과 **동일** — early stopping이 같은 자리에서 멈춤) · (0.02, 150, 31) 8.321 · (0.3, 150, 31) 8.660. 한 설정당 1~4초.
- **디버깅 체크리스트**:
  1. `KeyError`/인덱스 오류 → `reset_index(drop=True)`를 빼먹었다(`X_train`의 원래 인덱스는 섞여 있다).
  2. 전체가 1분 넘게 걸림 → `grid`를 3개로 줄인다.
  3. fold RMSE가 전부 비슷(예: 8, 8, 8, 8, 8) → `shuffle=True`인지, 데이터가 맞는지 확인(이 데이터는 **반드시** 요동한다).
- **확인 문제**
  1. `(코드 읽기)` fold 0의 RMSE 14.44, fold 4의 5.45. 두 fold의 "fold별 최대 y"와 나란히 놓고 요동의 원인을 말하라. SFR > 100을 빼고 재면 fold RMSE는 얼마쯤 될까(실측 3.7~4.4)?
     - 모범 답: fold 0에 y = 2145(전체 최대), fold 4의 최대는 334 → **어느 fold에 가장 큰 은하 몇 개가 들어갔나**가 RMSE를 정한다. 꼬리를 빼면 3.7~4.4로 **fold 간 차이가 거의 사라진다**. 즉 요동은 모델이 아니라 지표+꼬리의 성질. 채점 포인트: 최대 y와 RMSE 순서의 일치.
  2. `(계산)` 설정 (0.08, 150, 31)과 (0.08, 150, 7)의 CV 평균 차이는 0.10, fold SD는 약 4.0이다. fold가 독립이라고 (틀리게) 가정해 평균의 SE를 구하고, 이 차이로 둘을 가를 수 있는지 판단하라. 이미 배움 → 자분실 9 `[1단계 8/8]`(교수: fold MSE는 독립이 아니라 추론하지 않고 평균만).
     - 모범 답: SE ≈ 4.0/√5 ≈ **1.8** ≫ 0.10 → **가를 수 없다**(독립 가정이 틀려 실제 불확실성은 더 크다). 결론: 학습률 0.3만 나쁘고(8.66) 나머지는 구별 불가 → 기준선 설정을 그대로 두거나 **작은 트리**(잎 7)를 "단순함" 때문에 고를 수 있지만 "CV가 더 좋아서"라고 쓰면 안 된다. 채점 포인트: 잡음 아래의 차이.
  3. `(검토)` 5.1 초안: "하이퍼파라미터는 5-fold CV로 골랐다(CV RMSE 8.33). 최종 모델의 예측 RMSE는 8.33이다." 두 가지 오류.
     - 모범 답: (a) CV RMSE는 train의 80%(약 133k)로 학습한 모델이 train의 나머지에서 낸 값 — **val 점수가 아니다**(val은 9.5대). 보고할 성능은 val에서. (b) 설정 6개 중 최소를 골라 그 점수를 보고하면 **낙관적**(winner's curse) — 선택 점수와 보고 점수를 분리. 채점 포인트: 두 데이터셋의 역할.
- **막히면**: 1-1 2단계 2/2의 "은하 하나가 RMSE를 0.9 바꾼다" 계산을 fold 0(y = 2145)에 적용해 보인다: 2145를 500으로 예측하면 오차² 2.7 × 10⁶, fold 크기 33,350 → RMSE²에 81을 더한다 → 그것만으로 RMSE 9.
- **다음 회차까지**: 5.1·6.1 초안(§5 기준). CV 표를 노트북에 남긴다. 7절에 쓸 하이퍼파라미터 설정을 **하나 정하고 이유를 적는다**(예: 기준선 설정 유지 — CV가 구별하지 못하므로 변인 통제; 또는 잎 7 — 단순함).

### 3.4 받아야 할 출력 목록 (회차 끝에 모두 있어야 함)
1. 기준선 해부 출력(`n_iter_` 37, train/val RMSE, 음수 예측, 잔차 구간표)
2. 트리 수 곡선 숫자 9개 + 그림, 잎 수 4개 표
3. CV 표(6설정 × fold 5 + 평균·SD), fold별 최대 y

## 4. 2단계 설계 — 수학 (약 20분, 3블록)

### 4.1 목표
- 그래디언트 부스팅이 **함수 공간의 경사하강법**임을 제곱 손실에서 유도하고(잔차 = 음의 기울기, 잎 값 = 잔차 평균, η = 스텝), 다른 손실에서 잔차 자리에 무엇이 들어가는지 말할 수 있다.
- 회귀 트리의 분할 기준(SSE 감소 = 가중 평균 차의 제곱)을 유도하고 히스토그램 방식이 왜 단조 변환에 불변인지 설명할 수 있다.
- 잎 수·트리 수를 approximation–estimation으로 읽고, CV fold 잡음 아래의 차이가 왜 차이가 아닌지 말할 수 있다.

### 4.2 블록 계획
| 블록 | 제목 | 유도·증명 | 실습 연결 |
|---|---|---|---|
| 1/3 | 부스팅 = 함수 공간의 경사하강 | ℓ = ½(y − F)² → −∂ℓ/∂F = y − F(잔차); 잎 상수 최적화 → 잔차 평균; F ← F + η·h; 일반 손실의 음의 기울기(Poisson 예고) | 실습 1/3 `n_iter_`, 1단계 2/4 계산 문제 |
| 2/3 | 분할 기준과 히스토그램 | ΔSSE = (n_L n_R / n)(ȳ_L − ȳ_R)² 유도; 후보 임계값 = 구간 경계 → 순서만 씀 | 1단계 1/4 센티널·불변, 1-1 표준화 불필요 |
| 3/3 | 일반화와 CV 잡음 | nested 클래스 → 훈련 오차 단조; approximation–estimation; fold RMSE의 분산을 꼬리로 설명 | 실습 2/3·3/3의 숫자 |

### 4.3 블록 상세

#### [2단계 1/3] 부스팅 = 함수 공간의 경사하강
- **한 문장 직관**: 손실을 "예측값들의 함수"로 보고 그 기울기의 반대 방향으로 한 걸음 가는데, 그 방향을 트리로 근사한 것이 부스팅이다.
- **블록 목표**: (1) 제곱 손실에서 음의 기울기가 잔차임을 유도한다. (2) 잎 값이 잔차 평균인 이유와 η의 역할을 GD와 대응시킨다. (3) 손실이 바뀌면 잔차 자리에 무엇이 오는지 쓴다.
- **설명할 내용**
  - [필수] **설정**: 훈련 집합에서 예측 벡터 F = (F(x₁), …, F(xₙ))를 n개의 **파라미터**로 본다. 경험적 위험 L(F) = Σᵢ ℓ(yᵢ, Fᵢ). 이미 배움 → 심수기 7-2 `[1단계 2/8]` risk·empirical risk, 심수기 1 `[2단계 3/8]` 경사하강법 (`심층신경망의 수학적 기초/…`). **이 대회에서는**: 파라미터 공간이 아니라 **함수값의 공간**에서 GD를 한다.
  - [필수] **제곱 손실의 기울기**: ℓ = ½(y − F)² → ∂ℓ/∂F = −(y − F) → **−∇L = (yᵢ − Fᵢ)ᵢ = 잔차 벡터 r**. GD 한 걸음: F ← F − η∇L = F + η·r. 즉 "잔차를 더한다".
  - [필수] **왜 트리인가**: F + η·r은 훈련점 n개에서만 정의된다 — 새 x에서 r을 모른다. 그래서 r을 **x의 함수로 근사하는** 트리 h(x) ≈ r을 맞춰 F ← F + η·h. 트리는 유한한 함수 클래스라 "근사된 기울기 방향". 이것이 Friedman(2001)의 gradient boosting이다.
  - [필수] **잎 값의 유도**: 트리 구조(어느 점이 어느 잎인지)가 정해졌을 때 잎 j의 값 c_j는 그 잎 안의 손실을 최소화: min_c Σ_{i∈j} ½(yᵢ − F_i − c)² → ∂/∂c = −Σ(rᵢ − c) = 0 → **c_j = 잎 안 잔차의 평균**. 이미 배움 → 자분실 7 `[2단계 3/9]`(L2 → 평균 증명). **이 대회에서는**: HGB의 잎 값이 정확히 이것(제곱 손실일 때). 1단계 2/4 계산 문제의 −3, 3이 그 예.
  - [필수] **η와 M**: GD의 학습률과 반복 수. 작은 η·많은 M ≈ 같은 길을 잔걸음으로(실측 CV: 0.02·150 ≈ 0.08·150). 큰 η(0.3)는 걸음이 커서 거친 트리의 오차가 그대로 들어가 나빠진다(8.66). 심수기의 η < 2/L 같은 **정확한 수렴 조건은 없다**(트리 근사 때문) `[보충]` — 경험적으로 0.01~0.3.
  - [필수] **다른 손실** (2-1 예고 — 결과만): 로그 링크 Poisson deviance ℓ = μ − y log μ, μ = e^F → ∂ℓ/∂F = μ − y → 음의 기울기 = **y − μ**(여전히 "잔차"지만 F가 log μ라 잎 값은 평균이 아닌 다른 식). 분류 log loss → y − p. 즉 "잔차에 트리를 맞춘다"는 꼴은 같고 **잔차의 정의와 잎 값 공식**만 손실마다 다르다.
  - [선택] HGB는 잎 값에 2차 정보(Newton step, 손실의 2차 미분)를 쓴다 — 제곱 손실에선 2차 미분이 1이라 평균과 같다. 제곱 손실 외에서는 잎 값 = Σ기울기 / Σ2차미분.
- **확인 문제**
  1. `(증명·유도)` 손실을 ℓ = (y − F)²(½ 없이)로 두면 음의 기울기와 GD 한 걸음은 어떻게 되나? HGB 결과가 달라지나?
     - 모범 답: −∂ℓ/∂F = 2(y − F) = 2r → F ← F + 2η·r. 잎 값은 여전히 잔차 평균(상수 2는 c에 대한 최소화에 영향 없음)이므로 트리는 같고 **학습률이 2배**가 된 효과. sklearn은 잎 값을 손실 최소화로 정하므로 결과 동일 `[보충: 구현 세부]`. 채점 포인트: 상수 배는 η에 흡수.
  2. `(계산)` 1단계 2/4의 예(y = (0, 2, 4, 10), F₀ = 4, η = 0.5, 분할 x ≤ 2.5 고정)에서 **두 번째** 트리까지 더한 F₂와 SSE를 구하라. η = 1이면 F₂는?
     - 모범 답: F₁ = (2.5, 2.5, 5.5, 5.5), 잔차 (−2.5, −0.5, −1.5, 4.5) → 잎 평균 −1.5, 1.5 → F₂ = F₁ + 0.5·(−1.5, −1.5, 1.5, 1.5) = **(1.75, 1.75, 6.25, 6.25)**, SSE = 3.06 + 0.06 + 5.06 + 14.06 = **22.25**(56 → 29 → 22.25). η = 1: F₁ = (1, 1, 7, 7)(잎 평균을 다 더함), 잔차 (−1, 1, −3, 3) → 잎 평균 0, 0 → **F₂ = F₁** — 분할이 고정이면 한 걸음에 끝. 채점 포인트: η가 "일부만 더함"임을 숫자로.
  3. `(짧은 서술)` "early stopping은 함수 공간 GD에서 무엇을 조절하는 것인가"를 심수기 7-2의 세 오차(approximation·estimation·optimization) 용어로 한 줄.
     - 튜터용 맥락: 심수기 7-2 `[1단계 5/8]` estimation = optimization + generalization — 최적화를 덜 하면(ε_opt↑) 훈련 손실은 덜 내려가지만 generalization 항이 작아질 수 있다.
     - 모범 답: 반복 수 M을 줄여 **최적화를 일부러 덜 하는** 것 = optimization error를 남기는 대신 과적합(generalization/estimation)을 막는 정규화. 채점 포인트: "덜 최적화 = 정규화".
- **막히면**: 공방 1-1의 네 줄(순전파·손실·역전파·한 걸음)을 세로로 쓰고 옆에 부스팅의 네 줄(현재 F·잔차·트리 맞춤·F += η h)을 쓴다. "역전파"가 "잔차 계산"으로, "step"이 "트리 더하기"로.
- **다음 블록 연결**: 트리 h를 "잔차에 맞춘다"는 것은 구체적으로 어느 분할을 고르는 일인가.

#### [2단계 2/3] 분할 기준과 히스토그램
- **한 문장 직관**: 좋은 분할은 두 쪽의 평균이 많이 다르면서 두 쪽 다 충분히 큰 분할이다.
- **블록 목표**: (1) 한 분할의 SSE 감소량 공식을 유도한다. (2) 히스토그램 방식이 무엇을 바꾸고(속도) 무엇을 안 바꾸는지(순서 불변) 말한다.
- **설명할 내용**
  - [필수] **정리**: 노드 S(n개, 평균 ȳ)를 L(n_L, ȳ_L)과 R(n_R, ȳ_R)로 나누면
    **SSE(S) − SSE(L) − SSE(R) = (n_L n_R / n)(ȳ_L − ȳ_R)².**
    - 증명: SSE(S) = Σ_S(y − ȳ)² = Σ_L(y − ȳ)² + Σ_R(y − ȳ)². 각각 Σ_L(y − ȳ)² = Σ_L(y − ȳ_L)² + n_L(ȳ_L − ȳ)²(교차항 0 — 자분실 7 `[2단계 3/9]`의 MSE(c) = MSE(ȳ) + (c − ȳ)²와 같은 식). 따라서 감소량 = n_L(ȳ_L − ȳ)² + n_R(ȳ_R − ȳ)². ȳ = (n_Lȳ_L + n_Rȳ_R)/n을 넣으면 ȳ_L − ȳ = (n_R/n)(ȳ_L − ȳ_R), ȳ_R − ȳ = −(n_L/n)(ȳ_L − ȳ_R) → 감소량 = (n_L n_R²/n² + n_R n_L²/n²)(ȳ_L − ȳ_R)² = (n_L n_R/n)(ȳ_L − ȳ_R)². ∎
    - 읽기: **평균 차의 제곱 × 균형 가중치** n_L n_R/n(n_L = n_R일 때 최대 n/4). 한쪽에 1개만 떼는 분할은 평균 차가 커도 가중치가 작다 — `min_samples_leaf=20`이 그런 분할을 금지.
  - [필수] **탐욕적 선택**: 모든 피처 × 모든 임계값 후보에서 감소량 최대를 고른다(한 번에 한 분할, 되돌리지 않음). 부스팅의 잎 값은 잔차 평균이므로 분할 기준의 y를 **잔차 r**로 바꿔 읽으면 된다.
  - [필수] **히스토그램**: 임계값 후보를 "모든 서로 다른 값"(최대 n − 1개)이 아니라 **분위수 기준 255개 구간 경계**로 제한. 각 구간의 (Σr, 개수)만 누적하면 모든 후보의 감소량이 한 번의 스캔으로 나온다 → 트리 하나 O(n·d). 비용: 임계값 해상도가 255단계 — 20만 행이면 충분.
  - [필수] **단조 변환 불변의 증명**: 구간 경계는 **분위수**로 정하므로 x → g(x)(g 단조 증가)로 바꾸면 각 구간에 드는 점의 집합이 같다 → 모든 후보 분할의 (Σr, 개수)가 같다 → 같은 트리. 그래서 표준화·log 변환은 HGB에 영향이 없다(1-1 실습 3/3의 결정). 단, **비단조** 변환(|v|, 비율 stellar/halo 등 두 열의 조합)은 새 정보라 영향이 있다 — 완벽 ver 피처 공학의 근거.
  - [선택] 센티널 −6이 84%면 분위수 구간의 상당수가 −6 하나에 몰린다 — HGB는 같은 값은 한 구간으로 묶으므로 문제없다 `[보충: 구현]`.
- **확인 문제**
  1. `(계산)` 1단계 1/4의 6개 은하에서 분할 "밀도 ≤ 1.25"의 SSE 감소량을 공식으로 구하고, 직접 계산(13.33 − 2.67)과 맞춰라.
     - 모범 답: n_L = n_R = 3, ȳ_L = 3, ȳ_R = 1/3 → (3·3/6)(3 − 1/3)² = 1.5 × 7.11 = **10.67** = 13.33 − 2.67 ✓. 채점 포인트: 공식과 직접 계산 일치.
  2. `(증명·유도)` 같은 6개에서 "밀도 ≤ 2.1"(5:1 분할)의 감소량을 구하고, 왜 평균 차는 더 작지 않은데도 감소량이 작은지 가중치로 설명하라.
     - 모범 답: L = {3, 2, 4, 0, 1} 평균 2, R = {0} 평균 0 → (5·1/6)(2 − 0)² = **3.33** < 10.67. 평균 차 2 vs 2.67로 조금 작지만 **가중치 5/6 vs 1.5**가 결정적 — 한 점만 떼는 분할은 "균형" 가중치가 작다. 채점 포인트: n_L n_R/n의 역할.
  3. `(참/거짓 + 이유)` "`log10_stellar_mass`와 `log10_halo_mass`의 차(= log 비율)를 새 피처로 넣는 것은 트리에 아무 영향이 없다 — 두 열이 이미 있으니까."
     - 모범 답: **거짓.** 트리는 한 번에 한 피처의 임계값으로만 자르므로 "비율이 어떤 값보다 큰가"라는 **대각선** 경계는 많은 분할로 계단 근사해야 한다. 차 피처 하나면 질문 하나로 된다 → 영향 있음(단조 변환 불변은 **한 피처 안**의 변환에만 해당). 채점 포인트: 축 평행의 한계.
- **막히면**: 두 평균의 차를 "두 그룹을 얼마나 잘 갈라놓았나", 가중치를 "두 그룹이 얼마나 비슷한 크기인가"로 나눠 말한다. 1명 vs 5명으로 가르면 뭐든 "잘 갈라진" 것처럼 보이지만 쓸모가 없다.
- **다음 블록 연결**: 잎을 늘리고 트리를 늘리면 훈련 SSE는 끝없이 준다 — 검증은 왜 멈추나.

#### [2단계 3/3] 일반화와 CV 잡음
- **한 문장 직관**: 트리를 키우면 맞출 수 있는 함수는 늘지만 데이터 n개로 그 큰 클래스에서 맞는 것을 고르는 일은 더 불안해지고, 이 데이터에선 그 불안이 꼬리 몇십 개에 몰려 있다.
- **블록 목표**: (1) 잎 수·트리 수를 nested 함수 클래스로 보고 훈련 오차 단조성과 approximation–estimation을 적용한다. (2) fold RMSE의 요동을 꼬리의 분산으로 설명하고 "CV 차이 0.1은 차이가 아니다"를 정당화한다.
- **설명할 내용**
  - [필수] **nested 클래스**: 잎 k개 트리의 집합 ⊂ 잎 k+1개 트리의 집합(한 분할을 더 하면 되므로); 트리 M개의 합 ⊂ M+1개의 합(h_{M+1} = 0). 이미 배움 → 심수기 2-2 `[2단계 3/9]` 다항회귀와 과적합(nested면 training 오차는 단조 비증가), 심수기 7-2 `[2단계 1/10]`(approximation error는 중첩 클래스에서 단조 감소), `[2단계 6/10]` approximation–estimation trade-off. **이 대회에서는**: 실측 그대로 — 트리 150 → 1000: 훈련 4.94 → 1.73(단조↓), 검증 9.67 → 9.66(평평). 잎 3 → 31: 훈련 8.82 → 4.94, 검증 9.41 → **9.67**(↑). 즉 이 데이터·이 n에서는 작은 클래스가 total error 최소에 더 가깝다 — 피처가 꼬리를 설명하지 못해 approximation error의 바닥이 높고(어떤 클래스도 꼬리를 못 맞춤), 그 위에서 estimation만 커지기 때문 `[추정: 해석]`.
  - [필수] **왜 트리를 늘려도 검증이 "나빠지지는" 않나**: η = 0.08로 걸음이 작고 잎 평균이 매끄러운 추정이라 과적합이 느리다(실측 300까지 9.71 — 미미). 이것이 부스팅이 "과적합에 비교적 강하다"는 경험칙의 모습. 그래도 공짜는 아니다 — 시간과 early stopping 없는 재현성 문제.
  - [필수] **fold RMSE의 분산**: RMSE_k² = (1/n_k)Σ_{i∈k} eᵢ². eᵢ²가 극단적으로 치우쳐 있으면(61개가 85%) fold에 그 61개 중 몇 개가 들었나에 따라 RMSE_k²가 크게 변한다. 어림: 꼬리 은하 하나의 e² ≈ 2 × 10⁵(평균; 2145짜리는 2.7 × 10⁶), fold 크기 33,350 → 꼬리 하나가 RMSE²에 **6**을 더한다. fold 간 꼬리 개수 차 ±10이면 RMSE² ±60 → RMSE 5~10 사이를 오간다. 실측 [14.4, 10.3, 6.0, 5.4, 5.5]와 맞는다(fold 0에 2145 하나로 RMSE² +81).
  - [필수] **함의**: CV 평균 차 0.1은 fold SD 4.0 아래 → **"CV가 더 좋아서"는 쓸 수 없다**. 쓸 수 있는 말: "학습률 0.3은 명백히 나쁘다(8.66, 모든 fold에서 나쁨)", "나머지는 구별 불가 → 기준선 설정 유지(또는 단순성 때문에 작은 트리)". 이미 배움 → 자분실 9 `[2단계 8/9]` 교차검증의 수학(fold 의존성, 선택 후 낙관성).
  - [선택] 꼬리를 덜 민감하게 보는 방법: 꼬리 제외 RMSE를 **보조 지표**로 함께 보고(실측 3.7~4.4로 안정), 또는 stratified fold(SFR 구간별 층화)로 fold마다 꼬리 수를 맞춤 — 최종 보고서 선택지. 공식 지표는 바꿀 수 없다.
- **확인 문제**
  1. `(증명·유도)` "잎 k개 트리 집합 ⊂ 잎 k+1개 트리 집합"과 "트리 M개의 부스팅 합 ⊂ M+1개의 합"을 각각 한 줄로 보이고, 그래서 훈련 SSE가 k·M에 대해 단조 비증가임을 말하라. 검증 SSE에는 같은 말을 할 수 있나?
     - 모범 답: 잎 k 트리는 어느 잎 하나를 "같은 값 두 잎"으로 쪼개면 잎 k+1 트리 — 같은 함수. M개 합에 h_{M+1} ≡ 0을 더하면 M+1개 합. 포함 관계 → 더 큰 클래스의 최소 훈련 SSE ≤ 작은 클래스의 것(탐욕적 학습은 정확한 최소가 아니라 "대체로"). 검증 SSE는 **단조가 아니다** — 클래스가 커도 데이터로 고른 함수가 더 틀릴 수 있다(estimation). 채점 포인트: 포함 관계 + 훈련/검증 구분.
  2. `(계산)` fold 크기 33,350, 현재 RMSE 5.4인 fold에 y = 1414인 은하 하나가 추가되어 모델이 300으로 예측했다면 새 RMSE는 약 얼마인가?
     - 모범 답: e² = 1114² ≈ 1.24 × 10⁶ → RMSE² 29.2 + 1.24 × 10⁶/33,351 ≈ 29.2 + 37.2 = 66.4 → RMSE ≈ **8.1**. 은하 하나가 5.4 → 8.1. 채점 포인트: 제곱 척도 더하기.
  3. `(짧은 서술)` 보고서 5.1에 "CV로 하이퍼파라미터를 골랐다"를 쓰려면 어떤 **정직한** 한 줄이 따라와야 하나?
     - 모범 답 요지: "fold RMSE가 5.4~14.4로 요동(꼬리 은하 분포)해 설정 간 차이(< 0.4)는 잡음 아래였다 → 학습률 0.3을 제외하고는 구별하지 못했고, 기준선 설정을 유지했다(또는 단순성으로 잎 7)". 채점 포인트: 못 가른 것을 못 가렸다고 쓰기.
- **막히면**: 심수기 7-2 `[2단계 6/10]`의 총 오차 곡선(c/k² + σ²k/n)을 그리고 "이 데이터는 c/k²의 바닥이 높아서(꼬리를 어떤 k로도 못 잡음) k를 키우는 이득이 거의 없고 σ²k/n만 는다"고 말한다.

### 4.4 2단계 완료 체크리스트
- [ ] ℓ = ½(y − F)²에서 −∇L = 잔차, 잎 값 = 잔차 평균, F ← F + η·h를 유도하고 다른 손실에서 잔차가 y − μ, y − p로 바뀜을 말한다.
- [ ] ΔSSE = (n_L n_R/n)(ȳ_L − ȳ_R)²를 유도하고 가중치의 뜻을 말한다.
- [ ] 분위수 구간 → 단조 변환 불변을 증명하고, 비단조 조합 피처는 예외임을 말한다.
- [ ] 잎·트리 수를 nested 클래스로 보고 실측(훈련↓, 검증 평평/↑)을 approximation–estimation으로 읽는다.
- [ ] fold RMSE 요동을 꼬리 e²로 어림하고 "CV 차이 0.1은 차이가 아니다"를 정당화한다.
